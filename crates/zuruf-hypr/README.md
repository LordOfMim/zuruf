# zuruf-hypr

Öffentliche API: `src/lib.rs`. Eigenständige camelCase-kompatible Binding/Chord/BindingIssue-Typen, ohne `zuruf-core`. Gleichnamige Felder direkt in den Wirevertrag übernehmen. `Hyprland::detect(absoluter_zuruf_pfad)` erkennt Unavailable/Lua/Legacy durch Runtimeprobe. `available()` ist die Capability für globale Shortcuts; auf anderen Desktops ist apply/shutdown ein No-op. `prepare` prüft Modifier, Duplikate, Keycodes und Systemkonflikte vor einer Änderung. `diff` macht apply idempotent. Konfliktfehler tragen die vorhandene Beschreibung und Dispatcherargumente.

`apply(bindings)` betrifft nur globale Binds. Aktionsnamen werden gegen die Protokollliste geprüft, Binarypfade sind absolut und POSIX-gequotet; Lua erhält separat byteweise escapte Strings. Kein Webseiteninhalt gelangt als unkontrollierter Shellcode in den Dispatcher. Laufzeitregistrierung über `hl.bind`/`hl.unbind`, beim Legacyparser bindd/unbind. Letzteres ist implementiert, aber auf diesem Lua-Rechner nicht live abgenommen. Keine Konfigurationsdatei wird gelesen oder geschrieben.

Eigene Binds tragen `zuruf:<action>:<command-stamp>`. Nur exakt bekannte Aktionsbeschreibungen werden entfernt; liegt auf demselben Chord zusätzlich ein fremder Bind, wird Unbind abgelehnt (Hyprland entfernt alle passenden Binds). Ein einzelner aktiver Zuruf-Daemon wird vorausgesetzt. `serve(stop_rx)` hört auf `.socket2.sock`, verbindet nach EOF neu, wendet nach configreloaded erneut an und ruft beim Stop shutdown auf. Fehler oder Prozessabbruch können keine async Drop-Garantie bieten: der Besitzer muss shutdown auch auf Fehlerpfaden aufrufen. Kein Compositorreload wird zum Test künstlich ausgelöst. `find_window(pid)`, `focus(address)`, `arrange(address,w,h,x,y)` sind gezielte Helfer; Arrangement nur für verifiziertes Lua, keine heuristische Titelsuche.

Live abgenommen: SUPER+SHIFT+CTRL+ALT+F24 registrieren, in binds -j finden, entfernen, Abwesenheit prüfen. Keine Runtimebinds zurückgelassen. Keymapping liefert XKB-Namen für Buchstaben, Ziffern, F1–F24, Navigation und Satzzeichen; unbekannte Codes → unsupported_key. Die Zuordnung ist keysymsbasiert und muss auf tatsächlichen deutschen Tastaturlayouts manuell geprüft werden; Numpad und Multimediatasten werden konservativ abgelehnt.
